# ADR-0003: スキーマのマイグレーション方式

- ステータス: 承認（2026-10-28）
- 日付: 2026-10-25

## 結論

DB スキーマは **Flyway の SQL ファイル** を正とし、Flyway でマイグレーションする。EF Core はデータアクセス（クエリ、保存）にだけ使い、EF Core Migrations は使わない。

## 背景

- 最も重要な不変条件（重複予約の禁止）は、PostgreSQL の排他制約で保証する（ADR-0001）。スキーマそのものが、業務ルールの一部を担っている。
- ORM として EF Core を使い続けるとは限らない。DB はアプリのコードより長く使われるので、スキーマを特定の ORM に縛りたくない。
- 開発中の DB は、AppHost を起動するたびにまっさらな状態から作り直す。どの方式でも、起動時にマイグレーションを最初から流す仕組みが要る。
- 開発者は、今の現場で Flyway を使っている。

## 検討した選択肢

| | A: EF Core Migrations | B: Flyway |
|---|---|---|
| 正とするもの | C# のモデル（コードファースト） | SQL ファイル（DB ファースト） |
| マイグレーションの書き方 | モデルから自動生成し、必要に応じて生 SQL を足す | SQL を自分で書く |
| 排他制約（`EXCLUDE USING gist`） | Fluent API で表現できない見込み。`migrationBuilder.Sql` で生 SQL を埋め込む | 普通の SQL として書ける |
| ORM を替えるとき | マイグレーションの履歴ごと作り直しになる | スキーマはそのまま使える |
| モデルとスキーマのずれ | 自動生成なので起きにくい | 起きうる。手で同期する |
| 道具の数 | .NET の中で完結する | Flyway（Java 製）が増える。コンテナで動かすので、ローカルには何も入れない |

## 決定

**B（Flyway）を採用する。**

| 役割 | 担当 |
|---|---|
| スキーマの定義 | Flyway の SQL ファイル（`V1__*.sql` の形式） |
| マイグレーションの実行 | AppHost が Flyway をコンテナとして起動する。マイグレーションが終わってから API を起動する |
| データアクセス | EF Core。エンティティの設定（マッピング）は、SQL のスキーマに合わせて書く |
| 使わないもの | EF Core Migrations、`EnsureCreated` |

この決定の範囲は **開発環境とテスト** である。本番には AppHost がないので、本番でマイグレーションを誰がいつ流すかは未定（[TD-002](../tech-debt.md#td-002-本番のマイグレーション方法が未定)）。

## 結果

良くなること:

- スキーマが ORM から独立する。EF Core を Dapper などに替えても、スキーマはそのまま使える。
- 排他制約のような PostgreSQL 固有の機能を、そのまま SQL で書ける。不変条件を守る仕組み（ADR-0001）が、SQL ファイルを読めば分かる。
- 開発者が現場で慣れた道具なので、ハマる場所が少ない。

受け入れる代償:

- スキーマが SQL ファイルと EF Core のエンティティ設定の 2 か所に分かれる。ずれてもコンパイラは検出しないので、該当のクエリを実行したときに初めてエラーになる。本物の PostgreSQL に Flyway でスキーマを流し、EF Core 経由で読み書きする結合テスト（`RoomBooking.Api.Tests`）で検出する。
- モデルを変えるたびに、SQL とエンティティ設定の両方を手で直す。
- Flyway のコンテナという、動く部品が 1 つ増える。

フォローアップ:

- [ ] AppHost で Flyway を動かす方法を決める。コミュニティ製の `CommunityToolkit.Aspire.Hosting.Flyway` を使うか、`flyway/flyway` イメージを `AddContainer` で起動し `WaitForCompletion` で待つか。
- [ ] SQL ファイルの置き場所を決める（例: `db/migrations/`）。
- [ ] 開発用の初期データ（会議室など）の投入方法を決める。
- [ ] ADR-0001 の排他制約を、Flyway の SQL で実際に書けることを確かめる（フェーズ1）。
- [ ] Flyway のコンテナから Postgres のコンテナに接続できることを確かめる（接続先のホスト名。フェーズ1）。
- [ ] 本番でのマイグレーションの実行方法を決める（デプロイ先を決めるとき。TD-002）。
